# ESP-003 — Contrato de independencia y arquitectura

Estado: HECHA — contrato/arquitectura; no implementación Core ni release R1.

## Objetivo observable

Convertir “independiente de Rust” en requisitos auditables y definir el bootstrap, destinos, formatos, linker, seed, shims y herramientas esenciales antes de implementar Core.

## Responsabilidad, entradas y decisiones

Responsabilidad: `spec/independence.md`, `bootstrap/architecture.md`, política legible por máquina y validador. Entradas: inventario ESP-001, baseline ESP-002, producto MAT-001, fronteras MAT-002 y especificación MAT-003.

Decisión adoptada: stage0 Rust congelado → backend C transitorio → bootstrap Argorix → backend nativo ELF/PE-COFF. C queda prohibido en el build normal R1; el linker de sistema se permite sólo si está inventariado. Se rechazaron wrapper/binario estático/servicio Rust, backend que emite Rust y reescritura permanente en C porque no cumplen independencia.

## Criterios de aceptación

- [x] La política detecta wrapper Rust, servicio Rust, biblioteca Rust estática/procedencia Rust y backend que emite Rust; cada caso tiene control negativo reproducible.
- [x] Compiler, runtime, verifier, conformance, signer y package manager están dentro de la meta; omitir uno falla el candidato.
- [x] Linker, OS ABI, datos y shims permitidos requieren inventario; un linker externo no se oculta como cero dependencias.
- [x] C es transitorio y queda prohibido en N2/R1; backend nativo propio es condición de cierre.
- [x] Semilla publicada, fuentes `.argx`, formatos, perfiles Ubuntu/Windows y confianza/procedencia tienen contrato.
- [x] Compatibilidad MAT-003 y fronteras MAT-002 permanecen obligatorias; los documentos no atribuyen garantías no ejecutadas.

## Dependencias y límites

Dependencias no Argorix permitidas: kernel/ABI, linker fijado, bibliotecas no Rust auditadas, datos versionados y shims acotados; C sólo B0–N1. Versiones concretas de linker/CRT/crypto se fijarán con el candidato, no se inventaron aquí.

Dependencias Rust restantes: toda la implementación actual. ESP-003 sólo congela el criterio para retirarlas. No se construyó Core, seed, backend, ELF/COFF, bootstrap stage2/3 ni entorno limpio sin Rust. Los 9 casos son pruebas del detector sintético, no análisis binario/proceso/red real; ESP-024 debe implementar esos sensores y canarios.
