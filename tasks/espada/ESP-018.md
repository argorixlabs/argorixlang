# ESP-018 — The agent and policy language, migrated

Status: IN PROGRESS
Lane: Claude.
Dependencies: ESP-015 (PR #60). It uses the Core toolchain of ESP-010 to
ESP-016.
Date: 2026-09-26.

## Observable objective

Self-hosting must not mean dropping the ArgorixLang product that exists. The
work:

- migrate the declarations and rules inventoried in ESP-001: protocols,
  capabilities, modules, typed messages, governance and versions;
- build a compatibility matrix;
- fix divergences using the specification and the baseline;
- reuse the Core infrastructure without enabling additional effects.

The deliverables are an Argorix compiler for the whole language and a
feature-by-version functional matrix.

## Acceptance criteria (Plan Espada)

- [ ] Every item of the inventory has an implementation, or an explicit
      incompatibility accepted within scope.
- [ ] The applicable historical corpus passes.
- [ ] DENY, REVIEW and UNKNOWN do not turn into PASS through the migration.

## ESP-018.A

- **The lexer.** `compiler/agent_lexer.argx` follows L-01 of
  `spec/language/current-v1.md` and stage0 rule by rule:
  - UTF-8 is checked first;
  - `//` comments; strings with no escapes; unsigned integers below 2^64;
  - `{ } ( ) [ ] , : ->`;
  - identifiers that start with `_` or an alphabetic character and go on
    with `_`, `.` or an alphanumeric one;
  - errors do not stop lexing, and tokens are kept only when there was none.
- **Unicode.** "Alphabetic" and "alphanumeric" are Unicode's, as in stage0.
  - `compiler/unicode.argx` holds both properties, as trees of comparisons,
    so no table is built at run time.
  - It is generated from the Rust standard library stage0 uses (Unicode
    17.0.0) by `crates/argorixc/tests/unicode_tables.rs`. That test fails
    when the two disagree.
- **The dump.** `argorixc agent-tokens` and `compiler.agent_lexer.dump`
  print the same canonical dump (`spec/language/tokens.md`).

**Evidence.**

- `crates/argorixc/tests/agent_lexer_differential.rs` compiles
  `tests/selfhost/agent/lex_files.argx` through the C backend and runs it
  over 1,564 files:
  - every `.argx` file of the repository, both the agent-language corpus and
    Core sources;
  - 19 adversarial samples: Unicode identifiers, numeric digits and
    combining marks, emoji, unterminated strings at a line feed and at the
    end, integer overflow, several errors in one file, CRLF and tabs, and
    invalid UTF-8.
- All 1,564 dumps agree with stage0's.
- A companion test checks that the samples produce every token kind and
  every error.
- **Negative control.** With `alphabetic` false above U+00FF, exactly the
  two samples with non-ASCII letters disagree.
- `tests/selfhost/agent/cases.json` runs `lex_files` under gcc and clang,
  with and without sanitizers.

## ESP-018.B

`compiler/agent_parser.argx` parses the whole existing language into the
same syntax tree as stage0, the first error included.

- **Dump.** Every AST type derives `serde::Serialize`; `argorixc agent-ast`
  and `compiler.agent_parser.dump` print the tree as compact JSON, or the
  first error (`spec/language/ast.md`).
- **Generated from stage0's sources**, each checked by a test that fails
  when stale (`ARGORIX_BLESS=1` regenerates):
  - `compiler/agent_schema.argx`: every struct's fields in order and every
    enum's variants, from `ast.rs` (the `source_enum!` macro included);
  - `compiler/agent_words.argx`: 101 word tables, from every
    `"word" => Enum::Variant` arm of `parser.rs`;
  - the keyed-block declarations, 24 functions, from `parser.rs` by
    `crates/argorixc/tests/agent_blocks.rs`.
- **By hand:** the top level, `agent` and its handlers, `policy`, `type`,
  `enum`, `capability`, `tool`, `model`, `failure`, `assert`, `protocol`,
  `provider`, `feature`, `secret`, `crypto_boundary`, `passport`, and the
  scalar-keyed declarations (keys refused after their value) with their
  string objects.

**Evidence.** `crates/argorixc/tests/agent_parser_differential.rs` compiles
`tests/selfhost/agent/parse_files.argx` and compares 1,423 dumps with
stage0's: all 1,342 agent-language programs of the repository and 81
adversarial samples of the error paths. All 1,423 match, and none is left
unported. Changing one message fails exactly the sample that reaches it.
`tests/selfhost/agent/cases.json` runs `parse_files` under gcc and clang,
with and without sanitizers.

## How ESP-018.B was built

The parser (`parser.rs`, about 7,500 lines, 40 kinds of declaration) is
ported in several PRs, one group of declarations at a time. The pieces are
built in this order:

1. **The dump.** Every AST type derives `serde::Serialize`.
   `argorixc agent-ast` prints the program as one line of compact JSON, or
   its diagnostics (`parser::ast_dump`, `spec/language/ast.md`).
2. **The schema.** `compiler/agent_schema.argx` is generated from `ast.rs`
   and `span.rs` by a Rust test, as `compiler/unicode.argx` is:
   - every struct's fields, in declaration order;
   - every enum's variants and their shape (unit, one value, or fields).

   The Argorix side then writes fields in serde's order without anyone
   copying them by hand.
3. **The tree.** `compiler/agent_ast.argx` keeps the syntax tree as generic
   nodes (object of a schema struct, array, string, integer, bool, null,
   variant) and writes them as serde_json does, with its escaping.
4. **The parser.** `compiler/agent_parser.argx` ports `parser.rs`
   function by function:
   - the same `expect_*` helpers and messages;
   - the same first error: the stage0 parser stops at its first error;
   - the text-to-variant maps (for example `parse_policy_rule`) ported as
     they are.
5. **The differential** runs over the whole corpus from the start and
   counts the files that match exactly. A file that uses a declaration not
   yet ported is reported as such, not as a mismatch. Each PR raises the
   count; B is done when every file matches.

## ESP-018.C

`compiler/agent_check.argx` runs every check of stage0's `check_program`
(default options) over the tree of `compiler/agent_parser.argx`, in stage0's
order, and prints the same diagnostics, spans included
(`spec/language/check.md`).

- **Dump.** `argorix_semantics::agent_check_dump` and `argorixc agent-check`
  print `ok`, or one `line:column: message` line per diagnostic, or the
  parse error.
- **Ported in 14 groups**, each raising the differential's floor (the table
  in `check.md`): symbols, policies, tools, models, types, agents and their
  handlers, protocols; provider contracts, harnesses, features, secrets,
  adapters and their profiles, cryptos, DID methods, passports; the A-Trust
  declarations, trust ledgers, MCP and A2A bridges, evidence maps;
  governance, regulatory mappings, verifiers, conformance reports, runtime
  hardening, threat models, spec freezes, release candidates, runtime
  execution profiles and sandboxed adapters.
- **Stage0's semantics kept where they are easy to miss:**
  - `str::trim` over Unicode White_Space (`blank`, `trim_start`,
    `trim_end`);
  - maps built with `collect()`, where the last declaration of a name wins
    (`find_last`), next to sets where any declaration counts;
  - an enum's `source_name()`, the word itself for `Unknown` (`named`);
  - the placeholder span `1:1` of empty threat-model lists.

**Evidence.** `crates/argorixc/tests/agent_check_differential.rs` compiles
`tests/selfhost/agent/check_files.argx` and compares 1,462 dumps with
stage0's: every agent-language program of the repository, the parser's
adversarial samples and the checker samples of
`tests/selfhost/agent/check_samples/`. All 1,462 match and none is
`unsupported`. `tests/selfhost/agent/cases.json` runs `check_files` under
gcc and clang, with and without sanitizers.

**The module graph.** `compiler/agent_package.argx` ports `argorix_module`:
the `argorix.toml` manifest, path normalization, resolving the entry
module's imports depth first (unknown imports, duplicates, cycles, path
mismatches), and merging every module into one program that
`agent_check.check_tree` checks. The modules share one syntax tree
(`agent_parser.parse_into`); the merged program's lists hold the entry's
declarations, then each other module's by name. `argorixc agent-package`
prints stage0's dump (`spec/language/packages.md`).

**Evidence for the modules.**
`crates/argorixc/tests/agent_package_differential.rs` compiles
`tests/selfhost/agent/package_files.argx` and compares 79 dumps with
stage0's: the 50 packages of the repository, the 2 of the C fixture, and 27 adversarial packages in
`tests/selfhost/agent/package_samples/` (every manifest error, absolute,
drive and `..` paths, lexer and parser failures, missing, cyclic,
self-importing and re-imported modules, a diamond with a repeated import,
and diagnostics across merged modules). All 79 match.
`tests/selfhost/agent/cases.json` runs `package_files` under gcc and clang,
with and without sanitizers.

ESP-018.C is done.

## ESP-018.D plan

Stage0 lowers a checked program in three steps, each ported and compared on
its own over the whole corpus, as before:

1. **D.1, the IR** (`crates/argorix_ir/src/ir.rs`, `emit-ir`): the syntax
   tree without spans, enums as their source names, as pretty JSON. Most of
   `From<&Program>` is regular (a value, an optional value, a list of values,
   a nested list), so a table generated from `ir.rs` by a Rust test drives a
   generic walker; the few computed fields are written by hand: policy rule
   effects, an agent's effective approval, handler instructions, the
   resolved tool provider and the constant fields. Packages add their
   modules and imports (`package_ir`). **Done for one file:** the emitters
   are generated (`agent_ir_table.rs`), and all 1,462 dumps match, 557 of
   them lowered to IR; the generator also fixed 50 source names of the
   schema that rustfmt had wrapped.
2. **D.2, the bytecode** (`crates/argorix_bytecode/src/lower.rs`,
   `emit-bytecode`): the instructions lowered from the IR, and the source
   digest.
3. **D.3, the verifier's decisions** (`verify_bytecode`), on what D.2 emits
   and on serialized bytecode.

Each has a canonical dump for programs that do not check (their
diagnostics), so every program of the corpus is compared.

## Scope

The lexer and parser of the existing language, run through the stage0
frontend and the C backend like the rest of `compiler/`. They do not check
or lower yet (ESP-018.C and D).
