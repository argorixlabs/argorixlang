# ESP-018 — The agent and policy language, migrated

Status: IN PROGRESS
Lane: Claude.
Dependencies: ESP-015 (PR #60). It uses the Core toolchain of ESP-010 to
ESP-016.
Date: 2026-09-26.

## Observable objective

Self-hosting must not mean dropping the ArgorixLang product that exists. The
work:

- migrate the declarations and rules inventoried in ESP-001: protocols,
  capabilities, modules, typed messages, governance and versions;
- build a compatibility matrix;
- fix divergences using the specification and the baseline;
- reuse the Core infrastructure without enabling additional effects.

The deliverables are an Argorix compiler for the whole language and a
feature-by-version functional matrix.

## Acceptance criteria (Plan Espada)

- [ ] Every item of the inventory has an implementation, or an explicit
      incompatibility accepted within scope.
- [ ] The applicable historical corpus passes.
- [ ] DENY, REVIEW and UNKNOWN do not turn into PASS through the migration.

## ESP-018.A

- **The lexer.** `compiler/agent_lexer.argx` follows L-01 of
  `spec/language/current-v1.md` and stage0 rule by rule:
  - UTF-8 is checked first;
  - `//` comments; strings with no escapes; unsigned integers below 2^64;
  - `{ } ( ) [ ] , : ->`;
  - identifiers that start with `_` or an alphabetic character and go on
    with `_`, `.` or an alphanumeric one;
  - errors do not stop lexing, and tokens are kept only when there was none.
- **Unicode.** "Alphabetic" and "alphanumeric" are Unicode's, as in stage0.
  - `compiler/unicode.argx` holds both properties, as trees of comparisons,
    so no table is built at run time.
  - It is generated from the Rust standard library stage0 uses (Unicode
    17.0.0) by `crates/argorixc/tests/unicode_tables.rs`. That test fails
    when the two disagree.
- **The dump.** `argorixc agent-tokens` and `compiler.agent_lexer.dump`
  print the same canonical dump (`spec/language/tokens.md`).

**Evidence.**

- `crates/argorixc/tests/agent_lexer_differential.rs` compiles
  `tests/selfhost/agent/lex_files.argx` through the C backend and runs it
  over 1,564 files:
  - every `.argx` file of the repository, both the agent-language corpus and
    Core sources;
  - 19 adversarial samples: Unicode identifiers, numeric digits and
    combining marks, emoji, unterminated strings at a line feed and at the
    end, integer overflow, several errors in one file, CRLF and tabs, and
    invalid UTF-8.
- All 1,564 dumps agree with stage0's.
- A companion test checks that the samples produce every token kind and
  every error.
- **Negative control.** With `alphabetic` false above U+00FF, exactly the
  two samples with non-ASCII letters disagree.
- `tests/selfhost/agent/cases.json` runs `lex_files` under gcc and clang,
  with and without sanitizers.

## Scope

The lexer of the existing language, run through the stage0 frontend and the
C backend like the rest of `compiler/`. It does not parse or check.
