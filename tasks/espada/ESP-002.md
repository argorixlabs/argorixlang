## Objetivo y alcance

Conservar una referencia que permita detectar regresiones al construir Argorix en Argorix. Se fijaron compilador, lockfile, suites, fixtures y resultados del MVP Rust existente. La referencia no define por sí sola la semántica normativa (MAT-003) ni demuestra el build sin Rust (ESP-024).

## Comprobaciones y resultados observados

1. `git worktree add --detach` creó un checkout limpio del commit base; `git status --porcelain` quedó vacío. `cargo test --locked --offline --workspace --all-targets`: 382 pruebas en 29 binarios, cero fallos.
2. `cargo build --locked --offline --release` produjo los cuatro binarios de producto fijados por hash. El build `eval-tripwire` se hizo por separado y no se confundió con release.
3. El runner repitió 21 suites dos veces. Diecinueve suites pasaron sus 1.419 casos; `suite_min_v022.json` y `suite.v024.json` fueron rechazos esperados por rutas fuera del árbol portable. Trece goldens explícitos pasaron y el control negativo de golden modificado fue rechazado. Las huellas normalizadas coincidieron entre las dos pasadas.
4. El harness limpio y los binarios limpios ejecutaron E0–E4/E6 con snapshots E0 fijados en ZIP: 151 filas, 118/118 comparaciones puntuadas, 27 directorios completos y seis sólo con fuente, tamper 21/22, cero discrepancias, gates de anticircularidad/sensor en `go`. El manifest de esa corrida dice `worktree_dirty=false`.
5. Dos reruns offline y las 151 filas históricas coincidieron en ID, repetición, outcome, diagnósticos y campos observables seleccionados; SHA-256 normalizado `93B3EAC3D6990F1BE085A759EAD2C7B961F7DB5FEF2088E5525F3C1BFF4D4965`. No se afirma igualdad de timestamps, paths, nonces o bytes crudos.
6. La salida histórica E5 permanece intacta. El scorer corregido ya no dice que no se evaluó prompt injection: distingue las 80 llamadas históricas al modelo/driver de una resistencia **no evaluada** del bucle nativo Argorix. No se gastó API en esta tarea.

## Criterios de aceptación

- [x] Revisión, toolchain, dependencias, binarios y fuentes de fixture fijados por hash; checkout limpio verificado.
- [x] Build, tests, suites y adversarial offline ejecutados; controles negativos y errores esperados conservados en denominadores.
- [x] Cada golden tiene suite/caso/etapas esperadas, el ZIP E0 tiene origen y hash, y el runner usa perfil de normalización documentado.
- [x] Rerun offline reprodujo exactamente **lo declarado determinista**: etapas de suites y 151 campos observables proyectados; no se amplía esa afirmación a bytes crudos ni E5.
- [x] B4 corregido en nueva salida con test, preservando hash del resultado original y camera-ready.
