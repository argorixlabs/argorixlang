# ESP-005 — Memoria, efectos y ABI del host

Estado: HECHA — contrato ABI y prototipo Rust seguro; aún no implementado en stage0/C/nativo.
Revisión base: `5d73d663bf5b85fd71bdd0cbc1ac1636959d7e64`.
Dependencias: ESP-004 y MAT-004 cerradas con evidencia.
Fecha: 2026-09-19 UTC.

## Objetivo observable

Demostrar que el modelo M1/E1 puede sostener estructuras necesarias para el compilador sin UB, autoridad implícita ni dependencia de layouts Rust. Congelar la ABI lógica inicial para que ESP-006/007 implementen los mismos errores y ESP-008 pueda cruzar al runtime C transitorio.

## Alcance

- Contrato normativo `spec/core/memory.md` y ABI `spec/host-abi.md`/JSON.
- Prototipo transitorio Rust seguro dentro de `argorix-conformance`; no forma parte del release independiente.
- Pruebas de arena, generación, ownership, slices, préstamos, OOM, release, árbol y buffer expansible.
- Perfiles compiler-host, agent-runtime y verification-host separados por tipos/operaciones.
- Medición indicativa del costo de checks y techo de memoria; no benchmark de producción.

## Criterios de aceptación

- [x] Handles viejos, fuera de rango, liberados o de arena cerrada producen error tipado y nunca reviven.
- [x] OOM, overflow, borrow conflict, owner inválido y profundidad excedida dejan la operación atómica.
- [x] Árbol recursivo y buffer expansible funcionan dentro de límites medidos.
- [x] Texto/bytes/resultados tienen representación versionada sin puntero fabricable por Core.
- [x] FS, escritura, reloj, proceso y linker requieren capability y perfil compatibles; no existe FFI arbitraria.
- [x] Errores/layouts son estables y comparables entre backends objetivo.
- [x] Tests, canarios, hashes, costos, límites y carencias quedan en evidencia reproducible.
