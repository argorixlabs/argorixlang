# ESP-011 — Parser and AST in Argorix

Status: DONE (2026-09-23). Every acceptance criterion is met; merged in PR #54, and CI is green on `main@21b80ca`.
Lane: Claude, branch `claude/parser-esp011`.
Dependencies: ESP-010, DONE on 2026-09-23 (PR #53).

## Observable objective

Build the Core syntax tree with Argorix code. That means precedence,
declarations, functions, types and recovery, with recursive trees in the
approved memory model, preserved spans and nesting limits. The normalized AST
of the corpus is compared against the stage0 parser.

## Acceptance criteria (Plan Espada)

- [x] It parses all of its own sources and the lexer's.
- [x] It rejects errors and ambiguities as the grammar says, with the same
      diagnostics as stage0.
- [x] Deep inputs are cut off with a diagnostic, and the process neither
      overflows nor hangs.
- [x] Precedence and error fixtures exist.

## What exists

- `compiler/ast.argx`: the tree, and its canonical dump (`spec/core/ast.md`).
  - Nodes live in one buffer and link to their first child and next sibling
    by position. A child is always built before its parent, so no node owns
    another.
  - The dump walks the tree with an explicit stack, with no recursion.
- `compiler/parser.argx`: the parser.
  - Recursive descent, with precedence climbing for the ten binary levels.
  - Aggregates are allowed only where the grammar allows them.
  - `>>` is split when it closes two type arguments.
  - Recovery is per item.
  - Nesting stops at 256 levels.
  - Every step takes the parse state and returns it, because Core has no
    mutable references.
- `argorixc core-ast` prints the same dump from the stage0 parser.

## Found and fixed on the way

- **Stage0 had no nesting limit.** A debug `argorixc` overflowed the Windows
  main-thread stack near 55 levels of parentheses. Both parsers now report
  `NestingTooDeep` past 256 levels, and the driver runs on a 64 MiB stack.
- **C backend:** it refused to read a field of an element of a view,
  `tokens[at].line` with `tokens: Slice<Token>` (regression `g27`).

## Evidence

- `crates/argorixc/tests/parser_differential.rs` runs
  `tests/selfhost/parser/parse_files.argx` over 135 files through the
  compiler-host boundary and compares each dump with stage0's byte for byte.
  The files are:
  - `compiler/`, the parser's own sources and the lexer's;
  - `stdlib/`;
  - the stdlib, runtime and regression fixtures;
  - the spec corpus, valid and invalid;
  - the lexer's adversarial samples;
  - 13 parser samples:
    - precedence;
    - recovery across broken items;
    - types and patterns;
    - header errors, and a file with no version;
    - generics;
    - `if` followed by a parenthesis;
    - 300 levels of parentheses, blocks and types;
    - 200 unary operators;
    - an empty file.

  All 135 agree. A deliberate change to one label fails exactly the 73 files
  that contain binary operators.
- `tests/selfhost/parser/cases.json` runs `parse_files` in the harness, under
  gcc and clang with and without sanitizers, and checks the exact dumps it
  writes.

## Scope

This is a parser. It is not name resolution or type checking (ESP-012), and
the stage0 frontend still checks and emits it.
