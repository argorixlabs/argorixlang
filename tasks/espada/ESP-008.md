# ESP-008 — Transitional C backend and minimal runtime

Status: IN PROGRESS
Baseline: `13069ff02b3dcd6583e1fd75f1ab5ab2165e8d46` (`main` after ESP-007).
Dependencies: ESP-007 complete; verified Core IR boundary available.
Date: 2026-09-19 UTC.

## Observable objective

Compile verified Core 0.1 IR into deterministic portable C, build it with a
declared non-Rust C toolchain, and execute representative Core programs without
linking or invoking a Rust runtime.

## Scope

- A stage0 C emitter that accepts only `VerifiedCoreIr`.
- Explicit checked arithmetic, left-to-right evaluation, control flow, calls,
  aggregates, and the minimum memory/ABI operations required by fixtures.
- A small auditable runtime under `bootstrap/c/`, with no hidden Rust library.
- CLI emission/build paths that never construct shell commands from program
  text.
- Positive results and deterministic trap cases compiled and executed by a
  reproducible conformance runner.

## Acceptance criteria

- [ ] Representative Core fixtures emit valid deterministic C and execute with expected results.
- [ ] Checked overflow, division by zero, bounds, invalid handles, and resource limits fail deterministically where exercised.
- [ ] Generated C avoids signed-overflow and unspecified evaluation-order dependencies.
- [ ] The compiler invokes an allow-listed C compiler with argument arrays, never a source-derived shell string.
- [ ] Produced executables have no Rust runtime/library dependency and do not invoke Rust or Cargo.
- [ ] C emitter/runtime tests, workspace regression, formatting, Clippy, and CI pass.
- [ ] Evidence distinguishes transitional C execution from self-hosting, a native backend, or full Rust independence.
