# ESP-008 — Transitional C backend and minimal runtime

Status: DONE
Baseline: `13069ff02b3dcd6583e1fd75f1ab5ab2165e8d46` (`main` after ESP-007).
Dependencies: ESP-007 complete; verified Core IR boundary available.
Date: 2026-09-19 UTC.

## Observable objective

Compile verified Core 0.1 IR into deterministic portable C, build it with a
declared non-Rust C toolchain, and execute representative Core programs without
linking or invoking a Rust runtime.

## Scope

- A stage0 C emitter that accepts only `VerifiedCoreIr`.
- Explicit checked arithmetic, left-to-right evaluation, control flow, calls,
  aggregates, and the minimum memory/ABI operations required by fixtures.
- A small auditable runtime under `bootstrap/c/`, with no hidden Rust library.
- CLI emission/build paths that never construct shell commands from program
  text.
- Positive results and deterministic trap cases compiled and executed by a
  reproducible conformance runner.

## Acceptance criteria

- [x] Representative Core fixtures emit valid deterministic C and execute with expected results.
- [x] Checked overflow, division by zero, bounds, invalid handles, and resource limits fail deterministically where exercised.
- [x] Generated C avoids signed-overflow and unspecified evaluation-order dependencies.
- [x] The compiler invokes an allow-listed C compiler with argument arrays, never a source-derived shell string.
- [x] Produced executables have no Rust runtime/library dependency and do not invoke Rust or Cargo.
- [x] C emitter/runtime tests, workspace regression, formatting, Clippy, and CI pass.
- [x] Evidence distinguishes transitional C execution from self-hosting, a native backend, or full Rust independence.

## Record

  checked fixed-width arithmetic, sequenced calls/operands, control flow,

- The C1 runtime provides deterministic exit-70 traps, explicit step budgets,
  checked arithmetic, bounds/UTF-8 checks, and canonical 48-byte handle

- Ten source-level Core cases passed exact result/trap comparison under gcc,
  clang, and a Debian container with no Rust tools. ELF inspection found only
  the allow-listed C runtime dependency and all four negative controls detected
  their injected mismatch, process-spawn, Rust-symbol, or Rust-library signal.
- Local regression: formatting and Clippy passed; 418 workspace tests passed,

- Limitation: this is a transitional backend whose emitter remains Rust stage0
