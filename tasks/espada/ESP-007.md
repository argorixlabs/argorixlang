# ESP-007 — Executable Core IR and verifier

Status: DONE
Baseline: `43cb3ffcccd0f66aa2bfb3911dda41280f895677` (`main` after PR #19).
Dependencies: ESP-006 complete; Core 0.1 frontend and memory/ABI contracts available.
Date: 2026-09-19 UTC.

## Observable objective

Lower a semantically checked Core 0.1 program into a separately versioned, serializable IR and reject malformed IR before any backend can consume it. The IR must represent functions, values, control flow, calls, aggregates, memory intrinsics, and explicit effects without reusing the historical agent bytecode format.

## Scope

- Normative IR contract in `spec/core/ir.md` plus a machine-readable schema.
- Transitional Rust stage0 lowering and verifier isolated under `argorix_ir::core`.
- A verified wrapper type as the only input accepted by future Core backends.
- Canonical JSON roundtrip and semantic fingerprint checks.
- Direct negative fixtures for malformed types, missing references, invalid control flow, and unauthorized effects.
- CLI emission and verification commands that fail closed.

## Acceptance criteria

- [x] Core IR has an explicit version and cannot be confused with historical agent IR/bytecode.
- [x] All four valid ESP-004 programs lower and verify.
- [x] Serialized roundtrip preserves the verified semantic fingerprint.
- [x] Direct malformed IR tests reject type mismatches, missing references, invalid control flow, and unauthorized effects.
- [x] The future backend boundary accepts only `VerifiedCoreIr`, never raw/deserialized IR.
- [x] Historical compiler, conformance suites, formatting, and Clippy do not regress.
- [x] Evidence and limitations explicitly distinguish verified IR from execution, C output, self-hosting, and Rust independence.
