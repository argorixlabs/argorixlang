# ESP-010 — Lexer and diagnostics in Argorix

Status: IN PROGRESS
Lane: Claude, branch `claude/lexer-esp010`.
Dependencies: ESP-009, whose last part lands in PR #51. This task starts from
`main` and uses nothing that is still waiting in that PR.
Date: 2026-09-23.

## Observable objective

The first piece of the compiler written in its own language. The Core lexer
and its diagnostics are ported to Argorix, preserving:

- token semantics, comments, escapes and spans (byte, line and column);
- recovery after errors;
- structured diagnostics.

The port is compared against the specification and the stage0 baseline, not
only against stage0.

## Acceptance criteria (Plan Espada)

- [x] The lexer tokenizes its own sources.
- [x] Truncated input, invalid Unicode and invalid escapes produce bounded
      errors.
- [x] No Rust lexer runs underneath the Argorix lexer.
- [x] A table of resolved discrepancies exists (`spec/core/tokens.md`).
- [ ] The lexer reads its sources through the compiler-host boundary instead of
      as embedded arrays. This waits for PR #51.

## What exists

- `compiler/token.argx`: token kinds and the `Token` record.
- `compiler/diagnostics.argx`: structured diagnostics with stable codes,
  rendered as `line:column: lexical[Code]: message`.
- `compiler/lexer.argx`: the lexer. It validates UTF-8, counts columns in
  characters, nests comments, keeps going after errors, and ends with `Eof`.
- `compiler/token_dump.argx`: the canonical dump of `spec/core/tokens.md`, plus
  FNV-1a over it.
- `argorixc core-tokens` prints the same dump from the stage0 lexer.
  `argorixc --modules <dir>` adds a module directory, as `--stdlib` does.
- Two gaps closed on the way to executing this code:
  - string literals and `s.as_slice()`, whose bytes are a view under the usual
    view rules, now emit C;
  - `wrapping_add` now emits C.

  Both were valid Core that the C backend refused.

## Evidence

- `crates/argorixc/tests/lexer_differential.rs` compiles one Core program that
  embeds every sample, lexes it with the Argorix lexer and compares the FNV-1a
  of its dump with that of the stage0 dump. The samples are:
  - 16 adversarial inputs in `tests/selfhost/lexer/samples/`;
  - the lexer's own four sources;
  - the standard library;
  - the Core spec corpus, valid and invalid.

  All agree. A deliberate one-byte change to a token name makes exactly the
  samples that use that token fail.
- `tests/selfhost/lexer/lexer_basics.argx` checks structure (operator
  splitting, nested comments, suffixes, escapes, every diagnostic with its
  position). It passes with gcc and clang, with and without ASan/UBSan, and the
  CI job `stdlib` runs it.

## Scope

This is a lexer. It is not the parser (ESP-011) and not a self-hosted compiler,
and the stage0 frontend still checks and emits it. The dump makes the two
lexers comparable; it is not a new interface.
