# ESP-012 — Resolution, types and modules in Argorix

Status: DONE (pending review and CI on `main`)
Lane: Claude.
Dependencies: ESP-011 (PR #54).
Date: 2026-09-23.

## Observable objective

Move Core's semantic decisions out of Rust. That covers scopes, signatures,
calls, recursion, types, exhaustiveness, effects and the import graph, with
permitted and forbidden cycles resolved deterministically. Paths stay inside
the package, and compilation permissions are declared.

## Acceptance criteria (Plan Espada)

- [x] It validates its own sources: each module of `compiler/`, linked with
      the rest of the compiler and the standard library, checks `ok`, and so
      does `compiler/link.argx` itself.
- [x] It detects duplicate symbols, wrong types, missing returns, misused
      handles and invalid imports.
- [x] Its error decisions have independent tests: the stage0 checker and
      linker, compared byte for byte by two differentials.

## Subtasks

This follows the master plan's subdivision rule. The subtasks cut none of the
parent's criteria; together they meet all of them.

## ESP-012.A

- `compiler/check.argx` is the checker.
  - Types are interned in a table, so two types are equal exactly when their
    positions are.
  - Declarations and their members live in flat buffers. Names are source
    tokens, compared by text.
  - Scopes are a stack of bindings with a depth.
  - The checker follows the stage0 rules one by one, including where each
    diagnostic points.
- To give the checker what it reads, the parser now tags each node with:
  - its kind;
  - its name token;
  - the last token of its path;
  - a value: a literal, an operator or a length;
  - a flag: `pub`, `mut`, a guarded arm, or a suffix.
- `argorixc core-check-dump` prints the stage0 diagnostics in the same form
  (`spec/core/check.md`).
- **Stage0 fix:** two parts of the stage0 checker followed the iteration order
  of a hash map.
  - The order of `InfiniteType` diagnostics could change between runs; they are
    now reported in program order.
  - The lists of missing variants and fields in messages are now sorted.

**Evidence.** `crates/argorixc/tests/check_differential.rs` runs
`tests/selfhost/check/check_files.argx` over 140 files through the
compiler-host boundary and compares each dump byte for byte with stage0's,
without ESP-012.B's codes. The files are:

- the compiler, which includes the checker's own source;
- the standard library;
- every fixture corpus and the spec corpus;
- the lexer, parser and checker samples. The checker samples cover
  declarations, expressions and statements.

All 140 agree. Moving one diagnostic by one byte fails exactly the files where
it fires. `tests/selfhost/check/cases.json` runs `check_files` under gcc and
clang, with and without sanitizers.

## ESP-012.B

`compiler/check.argx` now also ports the stage0 ownership model:

- **Moves.** A binding moved on any path that reaches a use is
  `UseAfterMove`. Paths are joined wherever they meet: `if`, `match`, `&&`
  and `||`, and loops.
- **Moves in loops.** A binding declared before a loop and moved on a path
  back to its head is `MoveInLoop`.
- **Places.** A resource moved out of a field or an element is
  `MoveOutOfPlace`. A resource that is only inspected must be a place
  (`ResourceTemporary`), and one cannot live in an arena slot
  (`ResourceInArena`).
- **Views.** `as_slice()` is a view only as a direct argument
  (`SliceEscapes`), never alongside a move of the same storage
  (`SliceAliasesMove`).

The differential now compares the whole stage0 dump, with no codes set
aside, on 141 files, including a new ownership sample. All agree, and moving
one `UseAfterMove` by one byte fails.

One more C backend gap was closed on the way: assigning `Buffer::new()` to a
field now takes its type from the field (regression `g28`).

## ESP-012.C

- `compiler/link.argx` is the linker. It ports `core_link.rs` and the way the
  driver checks a package:
  - it lexes and parses the root and the files of its locked set, and merges
    their trees into one;
  - it orders the modules depth first from the root, and refuses a module
    declared twice, a cycle and a module outside the set;
  - it checks each module's import bindings and the public types they bring
    in by bare name;
  - it resolves `b.f` and `b.C` through the bindings, with stage0's scoping of
    locals, into paths that carry the item they name.
- `compiler/check.argx` now checks the merged tree. Each declaration keeps
  its module, and a named type is the declaration it resolves to rather than
  its text. Declarations are registered before their members are collected,
  so a type can still name one declared after it.
- Stage0: the driver's loop that links and checks each module as a root of
  its own moved into `check_core_package`, which `argorixc core-check` and the
  new `argorixc core-check-package-dump` share.

**Evidence.** `crates/argorixc/tests/link_differential.rs` runs
`tests/selfhost/check/link_files.argx` over 170 packages and compares each
dump byte for byte with stage0's. The packages are:

- every compiler module with the rest of the compiler and the stdlib;
- every stdlib module with the stdlib;
- the harnesses that import them;
- the multi-module conformance programs;
- the single files of the other corpora;
- 22 cases in `tests/selfhost/check/packages/`, one for each linking rule and
  for the order in which failures are reported.

All agree. Moving the position of one `PrivateSymbol` by one byte fails exactly
the two packages where it fires. Hiding the public types of imports fails every
package that uses one. `tests/selfhost/check/cases.json` adds a three-package
`link_files` case for gcc, clang and the sanitizers.

**Known difference.** Stage0 renames dependency items to `a__b__name`, so a
root item spelled like that collides with one; the Argorix checker does not
copy the renaming (`spec/core/check.md`).

## Scope

A checker in Argorix, still built and run through the stage0 frontend and the
C backend. It does not lower or emit code (ESP-013).
