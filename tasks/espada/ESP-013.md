# ESP-013 — Lowering and emission in Argorix

Status: IN PROGRESS
Lane: Claude.
Dependencies: ESP-012 (PRs #55, #56 and #57).
Date: 2026-09-24.

## Observable objective

Complete the path from Core source to executable from Argorix sources: the
IR, its verifier, lowering and the C backend written in Argorix. They respect
the contracts of ESP-007 and ESP-008, remove the Rust emitter from this path,
and emit a manifest of sources and options.

## Acceptance criteria (Plan Espada)

- [x] It compiles the programs of the corpus and the components of the
      compiler (ESP-013.C: byte-identical C, and a fixed point on itself).
- [x] The C it generates need not be identical to stage0's, but it must
      preserve semantics. Any difference in results is explained against the
      specification. (It is identical, so there is no difference to explain.)

## ESP-013.A

- `compiler/ir.argx` lowers a linked and checked package (`compiler/link.argx`)
  into the IR of `spec/core/ir.md`. It writes the IR's canonical JSON: the
  compact serialization whose SHA-256 is the semantic fingerprint.
- The document is the one stage0 builds, byte for byte:
  - the root's module with every module it reaches linked in, dependencies
    first;
  - dependency items renamed `a__b__name`, and every reference to them: types,
    `T::V`, aggregates, variant patterns, single-name paths that are not
    locals, and `m.f` / `m.C`;
  - the effect policy derived from the items, in `CoreIrEffect` order.
- The linker now returns everything it built (`compiler.link.link`). Its walk
  also records the item each non-local single-name path names, which is the
  one renaming that depends on scopes. String tokens keep their decoded text.
- Stage0: `argorix_semantics::core_package` loads a package as the driver
  does. `argorix_ir::core_package_ir_dump` and `argorixc core-ir-package-dump`
  print its canonical IR.

**Evidence.** `crates/argorixc/tests/link_differential.rs` runs
`tests/selfhost/ir/ir_files.argx` over the same 170 packages as the link
differential. It compares each IR byte for byte with stage0's, or checks that
both refuse the package. All agree, including every compiler module lowered
together with the rest of the compiler and the stdlib. Disabling the renaming
of single-name paths fails 38 packages. `tests/selfhost/ir/cases.json` runs
two packages under gcc, clang and the sanitizers in CI.

**Where the files live.** The plan names `compiler/ir/` and
`compiler/codegen/c/`. `argorixc --modules` reads one directory without
recursing, so the modules stay flat in `compiler/` (`compiler.ir`), as the
earlier phases do.

## ESP-013.C

- `compiler/c_emit.argx` is the transitional C backend, ported step for step
  from `crates/argorix_ir/src/core_c.rs`. It works on the linked tree and names
  things as the IR does (`compiler.ir` now exposes that naming). Stage0
  identifies types by string; here they are interned in a table. Stage0's
  maps are replaced by lists sorted the same way, and its `Result`s by a
  `failed` flag.
- It follows the same rules as stage0:
  - checked-arithmetic helpers and temporaries in evaluation order;
  - `&&` and `||` as branches;
  - ownership bookkeeping with `argorix_live_` flags and drop functions;
  - type definitions in dependency order;
  - the host shim only for programs that hold a capability.
  It also refuses the same programs: slices that escape, entries of the wrong
  shape, and constructs outside the profile.
- Stage0: `argorix_ir::core_package_c_dump` and `argorixc core-c-package-dump`
  print the C of a package, or `check failed` / `unsupported`.

**Evidence.**

- `link_differential.rs` runs `tests/selfhost/c/c_files.argx` over the same
  170 packages, and every output equals stage0's byte for byte:
  - 83 packages are emitted as C, the harnesses that hold the whole compiler
    included;
  - 26 are refused by both backends (library modules have no `argorix_main`);
  - 61 do not check.
- Two mutations are caught: sorting drop functions by C name fails 6 packages,
  and dropping the left-operand snapshot fails 25.
- **Semantics.** Identical C with the same C compiler means identical
  behaviour. It was also run:
  - The C the Argorix backend emits for the linker harness (1.25 MB, with the
    compiler and stdlib) compiles under `-Wall -Wextra -Werror`. It runs the
    `link_files` fixture with the expected dumps.
  - `the_argorix_c_backend_reproduces_itself_when_cc_is_available` checks a
    fixed point. Stage0 builds `c_files`, which emits C for its own package
    (lexer, parser, linker, checker, IR, C backend and stdlib). That C is
    stage0's byte for byte. Compiled, it emits the same bytes again (sha256
    `dde36a0e…` locally). The run is clean under ASan and UBSan.
- `tests/selfhost/c/cases.json` runs two packages under gcc, clang and the
  sanitizers in CI.

## ESP-013.D

- `compiler/pipeline.argx` runs every phase in `compiler/`: lexing, parsing,
  linking, checking and C emission (`compile`). It describes each build in a
  manifest (`manifest`), one line of JSON with:
  - the build's status;
  - the root module and the modules in link order;
  - each source with its path, module, size and SHA-256;
  - the C profile the output expects: C11, the warning flags, runtime ABI
    C1, whether it needs the host shim, and the default ceilings;
  - the output's size and SHA-256.
- `compiler/sha256.argx` is SHA-256 (FIPS 180-4) in Argorix. Core has no
  casts, so bytes become words bit by bit, and sums use `wrapping_add`.
- The Rust emitter is no longer on this path: the pipeline program is built
  once by stage0 as the seed, and everything it does after that is Argorix.

**Evidence.** In `link_differential.rs`:

- `the_argorix_pipeline_builds_and_describes_every_package_when_cc_is_available`
  builds 301 packages: the 170 of the differential, plus 131 files of every
  length from 0 to 130 bytes, which cover every padding case of the digest.
  Each C equals stage0's.
- Every field of every manifest is recomputed without Argorix: SHA-256 with
  the `sha2` crate, modules with stage0's parser, and link order with
  `core_link_order`.
- Changing one rotation of the digest fails the test.
- `tests/selfhost/pipeline/cases.json` runs two builds under gcc, clang and
  the sanitizers in CI.

## Scope

The whole path from source to C now runs in Argorix: lexing, parsing,
linking, checking, IR and emission. It still runs inside test harnesses built
by stage0. ESP-013.B, verifying IR read back from JSON, remains. ESP-014
assembles the compiler with its command line.
