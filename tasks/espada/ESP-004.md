# ESP-004 — Especificación ejecutable de Argorix Core

Estado: HECHA — especificación/corpus ejecutable; stage0 todavía no compila Core.
Revisión base: `5d73d663bf5b85fd71bdd0cbc1ac1636959d7e64`.
Dependencias: ESP-002, ESP-003 y MAT-003 cerradas con evidencia.
Fecha: 2026-09-19 UTC.

## Objetivo observable

Congelar el mínimo lenguaje de sistemas necesario para escribir lexer, parser, resolución, tipos, lowering y backend de Argorix sin invocar lógica Rust mágica. La implementación temporal en stage0 corresponde a ESP-006; esta tarea entrega gramática, semántica, corpus y un contrato verificable.

## Alcance y decisiones

- Core usa cabecera obligatoria `core 0.1;` y módulos versionados para no reinterpretar silenciosamente programas de agentes 1.0.
- Incluye funciones, recursión, variables, mutabilidad explícita, control de flujo, enteros fijos, bytes/UTF-8, arrays/slices/buffers, structs, enums, pattern matching, handles y módulos.
- Los argumentos de tipo sólo existen para contenedores intrínsecos (`Array`, `Slice`, `Buffer`, `Arena`, `Handle`); no se introducen genéricos de usuario, async, macros, clases ni FFI arbitraria.
- Overflow normal atrapa; wrapping debe ser explícito. Evaluación es izquierda a derecha. Los errores recuperables son variantes, no excepciones ocultas.
- El corpus `.argx` es especificación normativa aún no compilable por stage0. El verificador Rust comprueba integridad/cobertura del corpus, no finge parsear Core.

## Entregables

- `spec/core/` con lenguaje, EBNF, tipos, evaluación y módulos.
- `tests/selfhost/spec/` con programas positivos/negativos y manifest de casos.
- Validador Rust `core-spec-check` y pruebas del contrato en `argorix-conformance`.
- `bootstrap/ESP-004-validation.json` con revisión, hashes, cobertura y límites.

## Criterios de aceptación

- [x] Funciones, retornos, recursión, scopes y orden de evaluación quedan definidos.
- [x] Tipos, overflow, UTF-8, containers, structs, enums, handles y exhaustividad quedan definidos.
- [x] Control de flujo, acceso, llamadas, errores recuperables y módulos tienen caso positivo/negativo.
- [x] El corpus expresa un lexer, parser recursivo y tabla de símbolos sin llamada a Rust/Cargo/builtins mágicos.
- [x] La relación con Argorix 1.0 está versionada y cualquier interpretación ambigua falla cerrada.
- [x] Validador y pruebas verifican cobertura, fixtures, digests y control negativo.
