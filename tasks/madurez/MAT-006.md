## Pasos de implementación

1. Definir identidad del solicitante, recurso, operación, scope, presupuesto y caducidad de una capacidad.
2. Definir delegación atenuada: un hijo no amplía autoridad, duración ni presupuesto.
3. Definir revocación, cambio de políticas durante ejecución y punto final de comprobación previo al efecto.
4. Especificar cachés, condiciones TOCTOU, operación ya iniciada y fallos de consulta de autoridad.
5. Ejecutar las pruebas indicadas; guardar resultados y discrepancias. Corregir y repetir las pruebas afectadas.
6. Actualizar contratos, documentación y esta ficha con evidencias y dependencias restantes. No marcar HECHA antes de verificar todos los criterios.

## Criterios de aceptación

- [x] AC-1: delegation exige subset de operations/scope/audience/time/budget/depth; escenarios bloquean escalamiento y permiso retirado no se recupera.
- [x] AC-2: A1 define monotonic clock local, UTC firmado para tokens, error máximo objetivo ≤30 s y evaluación conservadora; modelo usa ticks exactos y lo declara como límite.
- [x] AC-3: revocación local antes del siguiente dispatch y feed distribuido objetivo ≤1 s; stale/unavailable → UNKNOWN. Before-commit deniega; after-dispatch → UNCERTAIN/cancel request, nunca rollback ficticio.

- [x] AC-COMÚN: 382/382 tests históricos pasan; final recheck conserva C1/E1 y la implementación actual sigue marcada declarativa, no A1.
