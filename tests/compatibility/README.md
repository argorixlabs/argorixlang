# Corpus de compatibilidad ESP-002

Este corpus es una referencia **histórica de regresión**, no una prueba independiente de corrección semántica ni de seguridad de producción. Fija el commit `5d73d663bf5b85fd71bdd0cbc1ac1636959d7e64`, el lockfile, toolchain, suites y expectativas en [bootstrap/baseline.json](../../bootstrap/baseline.json).

- [golden.json](golden.json): 13 casos revisables de etapas positivas y errores esperados en v016, v017 y v100. Las expectativas fueron escritas a mano a partir de la intención de cada suite y de la ejecución del binario fijado; son regresión, no oráculo semántico independiente. El runner compara ID, etapa y estado en orden; no compara texto diagnóstico, rutas absolutas, tiempos ni directorios temporales.
- Las 21 suites fuente siguen en `conformance/`. Diecinueve son ejecutables con el runner actual; `suite_min_v022.json` y `suite.v024.json` son entradas históricas que hoy se rechazan por rutas `../examples` fuera del árbol portable (y requisitos de categorías). Se fijan como **rechazo esperado**, no se omiten ni se cuentan como conformes.
- [e0-snapshots.zip](e0-snapshots.zip): archivo de 729.321 bytes con los 33 directorios de `demo/argorix-chatbot-runtime/generated/` observados el 2026-09-18; 27 contienen cinco artefactos, seis sólo `session.argx`. El hash SHA-256 y conteos están en el manifiesto. El ZIP compacta los snapshots existentes sin reescribir sus contenidos; `evaluation/adversarial/cases.json` enlaza cada E0 con su ID y `oracle.json` guarda el resultado esperado separado del colector. Se buscaron patrones comunes de claves/contraseñas y no hubo coincidencias; esa búsqueda no certifica ausencia de datos sensibles.

Para reproducir desde un checkout limpio del commit, construir los binarios de release con `cargo build --locked --offline --release -p argorixc -p argorix-vm -p argorix-conformance -p argorix-sign`. Ejecutar `python bootstrap/run-compatibility-baseline.py --repo <checkout-limpio> --bin-dir <checkout-limpio>/target/release --self-test` desde este workspace con el corpus. El runner exige commit limpio, versiones y hashes, recorre las 21 suites dos veces y registra fingerprints normalizados. Los pasos y resultados de la campaña adversarial offline figuran en [bootstrap/ESP-002-validation.json](../../bootstrap/ESP-002-validation.json).

E5 exige modelo real, versión, presupuesto y credenciales: no está incluida en el rerun offline. Su resultado histórico queda intacto; [la corrección B4](../../bootstrap/ESP-002-B4-correction.json) es sólo una nueva puntuación de los rows existentes y no una nueva llamada al modelo.
