\section{Methodology}\label{sec:methodology}

\subsection{Study design}
We conduct an observational, reproducible, non-controlled systems study.  The
unit of analysis is one request directory in an authorized snapshot of the
chatbot runtime's generated output.  The user authorized publication of the
runtime material.  Publication authorization does not relax minimization:
identifiers are aggregated, excerpts are bounded, and prompt content is not
reconstructed.

The design is observational because sessions were generated before the
analysis rather than assigned to controlled treatments.  It is reproducible
because committed scripts normalize the snapshot, generate tables and figures,
and rerun offline bundle verification.  It is non-controlled because there is
no randomized input, baseline runtime, repeated attack suite, or experimental
manipulation.  Consequently, counts describe this corpus and cannot estimate
attack success, causal effects, or population rates.

\subsection{Inventory and normalization}
The initial inventory contains 33 directories.  A complete directory must have
all five expected artifacts listed in \cref{sec:evidence}; 27 meet that
criterion and six contain only \code{session.argx}.  We retain incomplete
directories in the denominator and represent unavailable values as missing,
rather than silently discarding them.

The analysis parses available JSON, records parse errors, counts sizes and
artifact presence, extracts execution and policy fields, counts ledger-event
kinds, and records passport, runtime-profile, adapter, provider-boundary, and
digest metadata.  It writes one session row to \code{sessions.csv}, one
session/event-kind row to \code{event_counts.csv}, and a structured summary to
\code{runtime_summary.json}.  A separate PowerShell procedure invokes the
repository's offline evidence verifier for every complete bundle and stores
exit code and bounded standard output.

\subsection{Analysis rules}
We define in advance four interpretation rules.  A missing artifact is
``unavailable,'' never ``passed.''  A detailed policy result overrides a
coarser summary label for policy interpretation.  Successful evidence
verification means digest and reference consistency only.  Declarative records
are not counted as externally performed actions.

We aggregate complete-session policy violations and ledger events by summing
the normalized per-session fields.  We check all four evidence digest values
for the \code{sha256:} prefix and 64 hexadecimal digits.  The verification
result is successful only when the verifier exit code is zero and its explicit
verified flag is true.

\subsection{Prompt analysis boundary}
Although the user authorized publication, persisted artifacts contain prompt
content in 0 of 33 directories.  We therefore perform no prompt-level
qualitative analysis, quote no prompts, and report no prompt-injection attack
success rate.  Inferring prompts from request identifiers, trace shape, or
response metadata would be methodologically unsound and privacy-increasing.

\subsection{Threats to validity}
Construct validity is limited by our mapping of runtime fields to concepts such
as ``policy result'' and ``blocked attempt.''  We mitigate this by preserving
field names and reporting contradictions.  Internal validity is weak by
design: no causal intervention exists.  External validity is limited to one
snapshot and one runtime configuration.  Reliability depends on the committed
normalizer and verifier; generated CSV/JSON files permit independent checking.
Researcher interpretation remains a risk, particularly when declarative and
operational concepts share terminology.
